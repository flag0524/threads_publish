01

사람의 몫

글을 쓰고, 파일로 저장하고, 폴더에 넣는다. 여기까지가 전부다.

본문 500자 이내넘으면 발행 안 하고 큐에 남긴다
댓글 2~5편본문 아래 사슬로 이어진다
drafts/는 안 올라간다승인 대기 자리
여기까지만 하면
나머지는 알아서
① 락을 건다중복 실행 차단 · 1시간 넘으면 무효
② 오늘 몇 건인가이미 1건이면 그대로 종료
③ 한 건 고른다파일명 순 · 예약분은 건너뜀
④ 검증한다글자 수 · 금칙어 · 필수 필드
02

매일 밤 도는 파이프라인

스케줄러가 22:00에 깨어나 여덟 단계를 차례로 밟는다. 한 단계라도 막히면 멈춘다.

⑤ 토큰을 확인한다60일 수명 · 7일 전 자동 갱신
⑥ 컨테이너를 만든다생성 → 준비 확인 → 발행 (API 3회)
⑦ 댓글을 사슬로 단다5초 간격 · 각 댓글은 직전 글에
⑧ 파일을 옮긴다성공 published/ · 실패 failed/
Threads는 ‘바로 게시’가
없어서 세 번 부릅니다
계정 가드@flag_21이 아니면 발행 거부
재시도는 플래그로만429·5xx·네트워크 → 2s → 4s → 8s
토큰 오류는 즉시 중단190 · 401 · 403 — 다시 해도 같다
한 줄로 남는 이력history.jsonl · 본문 sha256
03

사고를 막는 층

무인 운영에서 가장 무서운 건 오류가 아니라 조용히 성공하는 사고다.

실패하면 알린다웹훅 1개 · 성공 알림은 없다
주 1회 생존 신호월요일 09:00 · 토큰 잔여와 큐 잔량
댓글 중간 실패 = partial메인은 이미 공개 · 수동 복구
같은 글은 두 번 안 나간다파일명 또는 본문 해시로 판정
월요일에 신호가 안 오면
스케줄러가 죽은 겁니다
